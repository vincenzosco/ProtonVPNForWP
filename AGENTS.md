# Agent instructions — ProtonVPNForWP

Applies to every AI agent (or human) making changes in this repository.

## Mandatory workflow: plan first, then execute the plan

This is not optional. Two skills, always, in this order, for **any non-trivial
change** (a new feature, a bug fix, a refactor, a tooling or CI change):

1. **Think with the planning skill first.** Load `writing-plans` and produce a
   written plan file before touching any source file. The plan must state, per
   task: the files it creates or edits, the exact interfaces it produces and
   consumes, the verification command, and the `Expected:` output of that
   command. Store plans under `.superpowers/plans/`.
2. **Then execute that plan with the execution skill.** Load `executing-plans`
   and run the plan task by task, in this same session, in order. Do not stop
   between tasks to ask whether to continue. Do not edit source outside the
   plan; if the plan turns out to be wrong, take a ruling, record it in the
   ledger as `Ruling: <decision> — <why> — <cost if wrong>`, and carry on.

The ledger lives at `.superpowers/sdd/<plan-name>/progress.md`. It is the
record: after any context loss, trust the ledger and `git log` over memory.

Skipping the plan, or writing a plan and then not executing it, is a defect in
the work regardless of how small the change looks. Only genuinely trivial work
(a typo in a string, a comment fix) is exempt.

## Project conventions

- **Language / toolchain:** VB.NET, Visual Studio 2013, MSBuild 12.0, Windows
  Phone 8.1 (Silverlight-free WinRT/XAML). `Option Strict Off` (see `.vbproj`).
- **VB12 limits:** no auto-implemented read-only properties, no null-conditional
  `?.`, no nameof, no string interpolation, no `ReadOnly` auto-property
  initializers. Write `.NET Framework 4.5` compatible VB.
- **No `System.Security.Cryptography`:** it does not exist for WP8.1. The app
  carries its own `Sha512`, `Bcrypt` and `SrpClient` implementations. Never
  reference the BCL crypto stack.
- **Bundled data:** the offline server catalogue is generated, never hand-edited.
  Regenerate with `python tools/make_bundle.py`.
- **Generated Blowfish tables:** `Services/Bcrypt.vb` embeds tables generated by
  `python tools/gen_blowfish.py`. Do not edit those constants by hand.

## Verification (required before claiming anything works)

1. `python tools/run_srp_harness.py` — compiles the shipping VB crypto sources
   with the desktop VB compiler and cross-checks SHA-512, bcrypt and the full
   SRP-6a exchange against the Python reference. All vectors must match.
2. Build the real project:
   `"C:/Program Files (x86)/MSBuild/12.0/Bin/MSBuild.exe" "Proton VPN WP/Proton VPN WP.sln" /p:Configuration=Debug /p:Platform=AnyCPU`
   — must finish with 0 errors.
3. `python tools/ocr_check.py` — renders the UI strings and compares the
   on-screen text against the expected labels.

A successful build is **not** proof that a feature works. State which command
you ran, and paste its actual result — never a "should pass".

## Rules a change must respect

- The endpoint, `/vpn/logicals` and the SRP/`auth` request shapes are Proton's
  public API contract; keep them in `Services/ProtonApiClient.vb` only.
- Never log passwords, SRP proofs, private ephemerals or vault contents.
- Adding a source file means adding it to `Proton VPN WP.vbproj` **and**
  (for XAML) to the `Page`/`ApplicationDefinition` item groups.
