# Architecture

Target platform: Windows Phone 8.1 (WinRT XAML, no Silverlight toolkit),
VB.NET, `Option Strict Off`, VB 12 language level.

## The constraint everything else follows from

**Windows Phone 8.1 gives third-party apps no VPN API.** There is no profile
installation and no tunnel control. Whatever the app does, the user connects
from the built-in VPN list.

So the app is designed as a *profile producer*: it does the part of Proton's
client that is actually possible here — authenticating, discovering servers, and
computing the exact IKEv2/OpenVPN fields — and it stops at the boundary the
platform draws. The UI states this rather than pretending otherwise.

## Layers

```
Views/        XAML pages. Code-behind: wire events, drive navigation, format.
ViewModels/   presentation state per page; no XAML types except none.
Services/     all behaviour: crypto, HTTP, SRP auth, catalogue, vault, connectivity.
Models/       data shapes; the Server/Profile/Preference types.
```

Pages never construct an HTTP client, a catalogue or a vault. `Services/AppServices.vb`
is the single composition root: one lazily created instance owning
`SettingsStore`, `CredentialVault`, `ProtonApiClient`, `ProtonAuthService` and
`ServerCatalog`, plus the current session and VPN credentials.

## Authentication: SRP-6a without a crypto library

Windows Phone 8.1 has no usable `System.Security.Cryptography` — no SHA-512, no
PBKDF2, nothing that reaches Proton's scheme. The app therefore carries its own:

| File | What it is |
|---|---|
| `Services/Sha512.vb` | SHA-512, because the BCL has none here |
| `Services/Bcrypt.vb` | bcrypt with Proton's `$2y$10$` variant, plus dot-slash base64 |
| `Services/BlowfishTables.vb` | generated Blowfish P/S initialisation constants |
| `Services/SrpClient.vb` | go-srp's SRP-6a: `expandHash`, `hashPasswordVersion3`, proofs |
| `Services/CryptoBytes.vb` | byte helpers, ASCII conversion, constant-time compare |

These four files are shared verbatim with a **desktop harness**
(`tools/run_srp_harness.py`) that compiles them with `vbc` and compares the
results against an independent Python implementation on fixed vectors: bcrypt
string, encoded salt, hashed password, client ephemeral, client proof, server
proof, shared session and two SHA-512 digests. Nothing else in this repository is
verified this tightly, deliberately: the rest fails loudly, cryptography fails
silently.

Two conventions must not drift, both inherited from go-srp:

- numbers cross the wire as **little-endian, fixed-width** byte arrays;
- `hashPasswordVersion3 = expandHash(bcrypt("$2y$10$" + dotSlashBase64(salt ||
  "proton"), password) || modulus)`.

Randomness lives outside `SrpClient` (`Services/RandomSource.vb`) so the crypto
stays pure and testable; the app uses `CryptographicBuffer.GenerateRandom`, the
harness injects a fixed value.

`Services/ProtonAuthService.vb` drives the exchange: `/auth/info` → compute
proofs → `/auth` → optionally the 2FA step. Tokens go to `CredentialVault`.

## The server catalogue

Proton's `/vpn/logicals` is not openly reachable, so `Services/ServerCatalog.vb`
layers three sources and records which one won (`CatalogueSource`):

1. **live API** when signed in and reachable — also written to a cache file;
2. **cache** in `ApplicationData.LocalFolder` from a previous successful call;
3. **bundled** `Data/servers.json`, generated by `tools/make_bundle.py`.

The order is deliberate: the app must be fully usable with no network and no
account, so a failure at step 1 is a downgrade, not an error. One parser
(`ServerCatalog.ParseLogicals`) reads both the live envelope
(`{"LogicalServers":[…]}`) and the bundled file, so the two can never drift.

## Secrets

`SettingsStore` handles non-secret preferences only. Everything secret — access
and refresh tokens, user id, the OpenVPN/IKEv2 username and password — goes
through `CredentialVault`, which encrypts each value with
`DataProtectionProvider("LOCAL=user")` before writing it. A copied settings file
is therefore not a credential dump. Settings → *Erase all app data* clears both.

`ProtonApiClient` logs method, path and status code. It logs no bodies. The
sign-in password is passed as an argument into the SRP code and never stored on
the view model, so it cannot reach a binding, a log line or a navigation
parameter.

## Navigation

`App` creates `MainPage`, which hosts the root `Frame` and the hardware back
button. Sign-in state decides the first page: `HomePage` when a stored session
restores, otherwise `LoginPage` (which offers an explicit offline path).
`ServerDetailPage` accepts a `ProtonLogical` as its navigation parameter and
falls back to the remembered server when launched without one, so deep links and
tiles cannot land on an empty page.

## Platform limits encoded in the code

Each of these has a comment at the point of use, and each is a small deliberate
workaround rather than a bug:

- `Encoding.ASCII` does not exist → `CryptoBytes.AsciiBytes` uses UTF-8, which is
  byte-identical for the ASCII-only inputs here.
- `Windows.ApplicationModel.DataTransfer.Clipboard` does not exist → the profile
  page shows read-only selectable text boxes instead of copy buttons.
- `StorageFolder.TryGetItemAsync` does not exist → a `GetFileAsync` probe wrapped
  in try/catch.
- `CryptographicBuffer.ToByteArray` does not exist → `CopyToByteArray`.
- Events declared on other types need `AddHandler` / `RemoveHandler`.
- VB12 has no read-only auto-properties, no null-conditional operator, no
  `nameof`, no string interpolation.
- File-level `Imports` must be **root-qualified** (`Imports Proton_VPN_WP.Models`).
  A bare `Imports Models` is silently ignored by the VB 12 compiler — it only
  produces a warning — and every type from that namespace then reads as
  undefined.
- `protected` is a VB keyword and cannot be used as a variable name.
